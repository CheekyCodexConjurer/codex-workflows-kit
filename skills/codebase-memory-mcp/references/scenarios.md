# Codebase Memory MCP — Independent Forward-Test Scenario Manual

This manual defines executable, deterministic verification scenarios for the parent orchestrator to forward-test the `codebase-memory-mcp` skill and tooling before production deployment.
All assertions must execute against actual system state; do not simulate, mock, or pretend real actions.

---

## Scenario 1: Read-Only and ALINHAMENTO Preflight Boundary

- **Objective**: Ensure that read-only, ALINHAMENTO, and COMMIT modes never mutate repository state, never invoke `index_repository`, never trigger background watchers, and never start processes on unprepared stores.
- **Pre-conditions**: Repository without an existing `.codebase-memory/` index or prepared store.
- **Execution**:
  1. Inspect index status using read-only query:
     ```powershell
     # Probe index status or use search_graph without write access
     pwsh -Command "Write-Output 'Testing read-only preflight: no auto-index allowed'"
     ```
  2. Verify that `index_repository`, `delete_project`, `manage_adr`, and `ingest_traces` are blocked.
  3. Verify that `readOnlyHint=true` is treated as advisory and does NOT authorize starting the CBM process or CLI on an unprepared store (which could trigger SQLite/WAL/cache creation).
  4. Verify that if no valid, already prepared store exists with a proven side-effect-free route, the agent falls back to `rg` with an explicit warning rather than auto-indexing or spawning CBM.
- **Expected Outcome**: Repository worktree remains completely untouched (zero untracked `.codebase-memory` or cache files created).

---

## Scenario 2: Exclusions and Canonical Root Verification (.cbmignore)

- **Objective**: Confirm that repository preparation enforces root `.cbmignore` exclusions for secrets, vendor folders, and generated artifacts before indexing.
- **Pre-conditions**: Repository root has `.cbmignore` with ignore rules (e.g. `*.key`, `vendor/`, `build/`).
- **Execution**:
  1. Check `.cbmignore` location:
     ```powershell
     Test-Path -LiteralPath ".cbmignore" -PathType Leaf
     ```
  2. Confirm that nested `.cbmignore` files in subdirectories are NOT treated as authoritative (CBM ignores nested `.cbmignore`).
  3. Verify discovery precedence:
     - Safety core (`.git`, `node_modules`, `.worktrees`) is strictly excluded and cannot be negated.
     - Non-safety built-ins can be un-skipped with `!dir/` in `.cbmignore`.
     - `.cbmignore` overrides git global excludes.
- **Expected Outcome**: Excluded directories and sensitive paths never enter the knowledge graph.

---

## Scenario 3: Swarm Concurrency and Atomic Indexing Lock

- **Objective**: Prevent multiple concurrent subagents from running redundant indexing on the same repository.
- **Pre-conditions**: Multi-agent swarm execution.
- **Execution**:
  1. Check for active project owner/lock before initiating `index_repository`.
  2. If an active lock exists or an index was freshly generated by a peer worker:
     - Worker reuses existing project identifier and graph store.
     - Worker skips redundant re-indexing.
- **Expected Outcome**: Exactly one index operation occurs per repository generation; zero race conditions on the project database.

---

## Scenario 4: Upstream Tool Annotations and Non-Read-Only Caveats

- **Objective**: Validate that tool handlers are correctly categorized by mutation safety according to upstream release v0.10.8 annotations, and enforce that `readOnlyHint=true` is advisory rather than proof of zero writes.
- **Verification Matrix**:
  - `search_graph`: `readOnlyHint=true`, `destructiveHint=false`, `idempotentHint=true`.
  - `query_graph`: `readOnlyHint=true`, `destructiveHint=false`, `idempotentHint=true`.
  - `trace_path`: `readOnlyHint=true`, `destructiveHint=false`, `idempotentHint=true`.
  - `get_architecture`: `readOnlyHint=true`, `destructiveHint=false`, `idempotentHint=true`.
  - `index_repository`: `readOnlyHint=false`, `destructiveHint=false`, `idempotentHint=true`.
  - `get_file_outline`: `readOnlyHint=false`, `destructiveHint=true` (Upstream caveat: touches project store / AST parse; must NOT be assumed pure read-only).
  - `manage_adr`: `readOnlyHint=false`, `destructiveHint=true`.
  - `delete_project`: `readOnlyHint=false`, `destructiveHint=true`.
- **Expected Outcome**: Agents in read-only modes never call tools flagged with `readOnlyHint=false` or mutation side effects, and do not spawn processes on unprepared stores even when `readOnlyHint=true`.

## Scenario 5: CLI One-Shot Execution Without Daemon Side Effects

- **Objective**: Verify that `codebase-memory-mcp cli` executes queries locally without starting or connecting to the long-lived coordination daemon, watchers, or UI server, and does not create database/cache/WAL artifacts in no-write modes without an already prepared store.
- **Execution**:
  ```powershell
  # Verify CLI invocation syntax on an already prepared store
  codebase-memory-mcp cli search_graph '{"project": "test-proj", "name_pattern": ".*"}'
  ```
- **Expected Outcome**: Command exits immediately after returning results; no persistent background process or HTTP server at port 9749 remains running; no store or cache mutation occurs in no-write modes.

---

## Scenario 6: Read-Only Diagnostics and Safe Rollback

- **Objective**: Inspect runtime health and logs without modifying state, confirm that `CBM_DIAGNOSTICS=1` is prohibited in routine/read-only inspection, and verify rollback via helper script.
- **Execution**:
  1. Inspect existing daemon logs under `${CBM_CACHE_DIR}/logs` (`cbm-daemon.log`, `daemon-conflicts.ndjson`) purely read-only without enabling active tracing.
  2. Confirm that `CBM_DIAGNOSTICS=1` is a mutation/logging opt-in and is prohibited from routine activation in read-only modes.
  3. Validate rollback via canonical helper:
     ```powershell
     pwsh -File scripts/install-free-mcps.ps1 -Mode Rollback
     ```
  4. Confirm that Antigravity desktop processes, user profiles, credentials, and OAuth tokens are never killed, restarted, or altered.
- **Expected Outcome**: Health diagnostics complete strictly read-only; rollback cleanly restores original configuration without collateral damage.
